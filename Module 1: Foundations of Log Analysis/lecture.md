# Introduction to Logs in Cybersecurity Operations

## 1. Overview

In cybersecurity operations, particularly from a Blue Team perspective, logs are essential for visibility, monitoring, and incident response.

- Logs serve as footprints of activities within systems, applications, and networks.
- They help security teams identify abnormal behavior and investigate malicious activity.
- Without logging, detecting suspicious activities and tracking security incidents becomes difficult.

Log Definition

A log is a timestamped record generated by a system, application, service, device, or security tool. It documents activities such as:

- User authentications
- Process executions
- Network connections
- File accesses
- Configuration changes
- System errors
- Security policy violations

## 2. Types of Logs by Source

| Source                     | Log Examples                       | Blue Team Use Cases                               |
| -------------------------- | ---------------------------------- | ------------------------------------------------- |
| Operating System (Linux)   | `/var/log/auth.log`                | SSH login attempts, sudo usage                    |
| Operating System (Windows) | `Security.evtx`                    | Logons, process creations, privilege usage        |
| Network Devices            | Firewall logs, DHCP logs           | Blocked traffic, address leasing                  |
| Web Servers                | Apache, Nginx access/error logs    | Suspicious URIs, 404 fuzzing, directory traversal |
| Security Tools             | EDR, antivirus, SIEM logs          | Threat detections, lateral movement               |
| Cloud Infrastructure       | AWS CloudTrail, Azure Activity Log | API misuse, privilege escalation attempts         |

## 3. Event vs. Log

- Event: A single instance or action, such as a user logging in.
- Log: The written record of an event, which may be structured (JSON) or unstructured (plaintext).

Common Log Fields

Every log contains at least:

- Timestamp
- Source or system
- Description of the event

Additional fields depend on the software or hardware generating the log.

## 4. Real Examples of Log Entries

### 4.1 Linux SSH Authentication Failure

```
Jun 20 18:45:32 ubuntu sshd[2541]: Failed password for root from 192.168.1.23 port 49522 ssh2
```

Interpretation:

- An SSH password attempt for the root user was rejected.
- The connection originated from IP address `192.168.1.23`.

Blue Team Application:

- Correlate multiple failed login attempts.
- Identify potential brute-force activity.

### 4.2 Windows Logon Event (Security.evtx, Event ID 4624)

```
Log Name: Security
Event ID: 4624
Logon Type: 10
Account Name: Administrator
Source Network Address: 10.0.0.14
```

Interpretation:

- A successful Remote Desktop Protocol (RDP) login occurred.
- The Administrator account was accessed from `10.0.0.14`.

Blue Team Application:

- Detect unauthorized RDP access.
- Investigate potential lateral movement.

### 4.3 Web Server Access Log (Apache)

```
192.168.1.50 - - [29/Jun/2025:14:23:42 +0000] "GET /admin HTTP/1.1" 401 487
```

Interpretation:

- Client `192.168.1.50` attempted to access the restricted `/admin` area.
- The server returned `401 Unauthorized`.

Blue Team Application:

- Detect suspicious probing.
- Identify potential brute-force attempts against login or admin portals.

### 4.4 IDS Alert (Suricata JSON Format)

```
{
  "timestamp": "2025-06-29T16:21:00.512293Z",
  "event_type": "alert",
  "src_ip": "192.168.1.10",
  "dest_ip": "10.10.1.23",
  "alert": {
    "signature": "ET SCAN Nmap -sS Syn Scan",
    "severity": 2
  }
}
```

Interpretation:

- The intrusion detection system identified a SYN scan likely originating from Nmap.
- The alert contains the source IP, destination IP, timestamp, and severity.

Blue Team Application:

- Perform alert triage.
- Investigate the source of the activity.
- Trigger event correlation in a SIEM.

## 5. Why Logs Are Critical for Blue Teams

1. Visibility
   - Provide insight into user activity, system changes, and potential threats.
2. Forensics
   - Serve as a timeline for post-incident investigations.
3. Detection Engineering
   - Support detection rules in SIEM and EDR platforms through log-based patterns.
4. Compliance and Auditing
   - Provide logging evidence required by regulatory frameworks such as PCI-DSS, HIPAA, and ISO 27001.
5. Threat Hunting
   - Enable hypothesis-based searches to uncover stealthy attackers.

## 6. Common Blue Team Use Cases Involving Logs

| Use Case                            | Related Log Types                          |
| ----------------------------------- | ------------------------------------------ |
| Detect brute-force attacks          | SSH logs, Event ID 4625 (Windows)          |
| Investigate privilege abuse         | Event ID 4672 (Windows), sudo logs (Linux) |
| Detect suspicious command execution | Event ID 4688, Sysmon, bash_history        |
| Trace lateral movement              | RDP logs, SMB connections, port scans      |
| Identify web attack vectors         | Apache/Nginx access logs, WAF logs         |
| Monitor file access or exfiltration | File integrity logs, EDR telemetry         |

## 7. Logging Pitfalls to Avoid

- No Central Logging: Local logs can easily be erased by attackers.
- No Time Synchronization (NTP): Event correlation becomes unreliable.
- Unstructured Logging: Makes automation and parsing more difficult.
- Insufficient Retention: Limits historical analysis and investigations.
- Excessive Log Noise: Important security signals can get buried without proper filtering.

## 8. Key Takeaways

- Logs are fundamental to cybersecurity operations and Blue Team activities.
- They provide visibility into system, application, network, and user activities.
- Different log sources provide different insights for security monitoring and investigation.
- Log analysis supports threat detection, incident response, forensics, compliance, and threat hunting.
- Centralized logging, time synchronization, proper retention, and structured data are important for reliable security monitoring.

## 9. Key Application

- Analyze Linux authentication logs to identify suspicious SSH login attempts.
- Review Windows Event IDs to investigate successful logons, failed authentications, and privilege usage.
- Examine web server logs for suspicious requests and unauthorized access attempts.
- Investigate IDS alerts to identify potential network reconnaissance.
- Correlate logs from different sources to detect brute-force attacks, privilege abuse, and lateral movement.
